1Added labels to the form inputs

Audit: “Form elements do not have associated labels” (Names and labels).

Why it matters: A screen reader needs a label to tell the user what an input is for. Placeholder text or a nearby paragraph is not counted as a label.

Before

<p>Enter a score:</p>
<input type="number" id="scoreInput">

After

<label for="scoreInput">Enter a score:</label>
<input type="number" id="scoreInput">

The same change was made for the “Enter a number:” input and the name input (a hidden label, so the design stays the same).

2Wrapped the page content in <main>

Audit: “Document does not have a main landmark” (Best practices).

Why it matters: The main landmark lets screen reader users jump straight to the page content.

Before

<body>
  <h1>JavaScript Basics</h1>
  ...sections...
</body>

After

<body>
  <main id="main-content">
    <h1>JavaScript Basics</h1>
    ...sections...
  </main>
</body>

3Added a skip link (WCAG 2.4.1, Level A)

Why it matters: Keyboard users otherwise have to tab through every link before reaching the content. The link is hidden until it receives focus.

HTML (first element inside body)

<a href="#main-content" class="skip-link">Skip to main content</a>

CSS

.skip-link { position: absolute; left: -9999px; }
.skip-link:focus {
  left: 0.5rem; top: 0.5rem; z-index: 9999;
  background: #1a2744; color: white; padding: 0.5rem 1rem;
}

How to test: Open the page, press Tab once, and the “Skip to main content” link appears at the top left. Press Enter to jump to the content.

Other small improvements

  • Added a viewport meta tag so the page scales on phones.
  • Added a visible keyboard focus outline.
  • Added role="status" to the result messages so screen readers announce them.

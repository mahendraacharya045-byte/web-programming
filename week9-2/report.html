1. Summary

I ran Lighthouse on my coursework hub, applied several optimizations to its HTML, CSS and JavaScript, and ran Lighthouse again. The Performance score improved from 99 to 100.

2. Test setup

  • Tool: Lighthouse 13.5.0 in Chrome DevTools
  • Mode: Mobile (emulated Moto G Power, slow 4G throttling), Performance category
  • Before run: 2:30 PM, score 99
  • After run: 2:46 PM, score 100
  • Both runs used the same URL and the same browser profile, so the comparison is like for like.

3. Baseline findings (before)

  • Minify JavaScript: estimated savings of 60 KiB
  • Reduce unused JavaScript: estimated savings of 484 KiB
  • Avoid long main-thread tasks: 5 long tasks found

My page loads no external libraries, scripts or fonts, so the large unused-JavaScript figure most likely came from browser extensions active in my profile rather than from my own code. I could not confirm this directly, so I treated my own inline script as the part I could actually improve.

4. Optimizations applied

  1. External, minified, deferred JavaScript. I moved the inline script into app.min.js and load it with defer. It no longer blocks HTML parsing and the browser can cache it.
  2. Minified CSS. I removed whitespace and comments from the inline stylesheet, reducing it to about 6 KB.
  3. content-visibility: auto on week cards. The browser skips rendering work for off-screen cards, which reduces main-thread work during load.
  4. More efficient search script. DOM lookups and lowercase text are computed once instead of on every keystroke, and input is debounced by 100 ms.
  5. Targeted CSS transitions. I replaced a catch-all transition: .2s with specific properties so the browser animates only what changes.
  6. Inline favicon and meta description. The data-URI favicon avoids a failed /favicon.ico request, and the description helps search engines.

5. Code quality fixes made along the way

  • URL-encoded the spaces in the Week 1 and Week 2 link paths.
  • Corrected the Week 8 task count (4 to 5) and the footer total (29 to 49).
  • Cleaned up inconsistent labels such as "week9".

7. Conclusion and limitations

The page was already fast, so the headroom was small, but the changes moved it to a perfect 100 and made the code cleaner and cheaper to run. Lighthouse scores vary slightly between runs, so a one-point difference shows a direction of improvement, not a precise measurement. A fairer follow-up would repeat each run several times in an Incognito window with extensions disabled.

8. Description for the website (2 sentences)

I moved my JavaScript into a minified file loaded with defer, minified my CSS, and added content-visibility: auto so off-screen week cards are not rendered up front. I also made the search more efficient and removed a failing favicon request, which raised my Lighthouse Performance score from 99 to 100.
